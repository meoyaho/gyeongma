# 말 달리자

말 이름을 부르는 횟수로 가속하는 한국어 웹 경마 게임. 준비·대기 화면의 말 이미지 8종, Three.js 1인칭 경주, Web Speech API 음성 인식, WebSocket 실시간 경주 서버를 포함합니다.

## 실행

Node.js 20.19 이상이 필요합니다.

```sh
npm install
cp .env.example .env
# .env에서 OPENAI_API_KEY를 설정한 뒤 실행
npm run dev
```

http://localhost:3000 에서 실행됩니다. `PORT` 환경변수로 포트를 바꿀 수 있습니다.

이미 `.env`가 있으면 덮어쓰지 마세요. 서버가 `.env`를 자동으로 읽으며, 운영 환경에서는 호스팅 서비스의 비밀 환경변수 `OPENAI_API_KEY`를 설정합니다. 키를 변경하면 Node 서버를 재시작하세요. 키는 클라이언트에 보내지 않고 Git·Docker 이미지에서도 제외합니다. 키가 없거나 API 심사에 실패하면 이름을 승인하지 않습니다.

```sh
npm run build
npm start
```

프로덕션에서도 Node 서버를 실행해야 합니다. `dist`만 정적 호스팅하면 멀티플레이와 이름 검증 API가 동작하지 않습니다.

## 게임

- 이름: 띄어쓰기 없이 완성형 한글 4~6글자. 자모, 숫자, 영문, 기호를 차단합니다.
- "네" 바로 뒤에 흔한 명사(말·집·밥 등)가 오는 이름은 차단합니다. 예: "지수네말". 음성 인식이 비격식 소유격 "-네"를 문법적으로 더 흔한 격식 소유격 "-의"로 바꿔 알아듣는 경우가 많아, 실제로 말한 이름과 인식 결과가 계속 어긋나기 때문입니다. `shared/rules.js`의 짧은 명사 목록으로 판단하며 이 목록에 없는 명사는 걸러내지 못할 수 있습니다. 이는 의미·품위 심사가 아니라 인식 정확도를 위한 구조 검사로, 아래의 의미 기반 금칙어 미사용 원칙과는 별개입니다. 사용자에게는 구체적인 규칙을 설명하지 않고 "음성 인식이 헷갈릴 수 있는 이름이에요."라는 일반적인 안내만 표시합니다.
- 수동 금칙어 목록을 사용하지 않습니다. `shared/rules.js`는 형식만 검사하고, `server/name-moderation.js`에서 OpenAI Responses API의 **GPT-5 nano**가 유명인·정치인·회사·상품·광고·부적절한 표현을 의미와 문맥으로 심사합니다. 분류와 짧은 근거를 엄격한 JSON 스키마로 받고, 사용자에게는 서버가 정한 경고만 표시합니다. 무해한 일반 단어의 우연한 음절 일치는 허용하도록 지시합니다. AI 판정에는 누락·오탐이 있을 수 있으며 최신 인물·상표를 실시간 검색하지는 않습니다. 표기를 살짝 바꾼 유명인 오마주 이름(예: "강다니엘"을 흉내 낸 "간다니에")은 차단하지 않습니다 — 다만 음성 인식이 원래 유명인 이름으로 알아들어 인식 횟수가 세어지지 않을 수 있고, 이를 자동으로 보정하는 기능은 시도했으나 저비용 모델의 정확도가 낮아 넣지 않았습니다.
- 2026-09-12 확인한 [공식 가격표](https://developers.openai.com/api/docs/pricing)에서 GPT-5 nano의 Standard 토큰 단가는 입력 100만당 $0.05, 출력 100만당 $0.40입니다. 낮은 추론 강도, 최대 출력 1,024토큰(추론 포함), 웹 검색 미사용, 동일 이름 24시간 캐시·진행 중 요청 병합으로 비용을 제한합니다. 입력할 때마다 호출하지 않고 확인 버튼과 서버 입장 검사에서만 검사합니다. 실제 요금은 입력·추론·출력 토큰 사용량에 따라 달라집니다.
- 이름만 OpenAI에 전송하며 `store: false`로 응답 저장을 비활성화합니다. 모델 거절·불완전한 응답·API 장애는 허용 판정으로 바꾸지 않고 재시도를 안내합니다. HTTP와 WebSocket 이름 요청에 동일한 IP별 분당 30회 제한을 적용하며, 전체 심사는 최대 6개를 동시에 처리합니다.
- 사용자가 **확인**을 누르면 서버가 [한국마사회 호스피아 마명조회](https://www.horsepia.com/hp/pa/hh/PAHH2060/index.do)의 동일·유사 마명 목록을 조회합니다. 반환된 등록마 중 이름이 정확히 같으면 퇴역·사망 여부나 마사회의 재사용 허용 여부와 관계없이 거절합니다. 경주마 이외 등록마도 조회 결과에 포함되면 같은 기준을 적용합니다. 유사하기만 한 이름은 거절하지 않습니다. 이름만 등록된 제한 항목도 거절합니다.
- `server/name-check.js`의 마사회 조회는 공개 페이지가 사용하는 요청을 이용하며 별도의 마사회 API 키는 필요하지 않습니다. 서버의 외부 HTTPS 연결이 필요합니다. 조회 실패·시간 초과·응답 형식 변경 시 이름을 승인하지 않습니다. 최종 성공 결과는 5분, 제한 결과는 24시간 메모리에 캐시합니다. 공식 조회에서 반환되지 않는 이력까지 보장하지 않으며, 조회 방식이 변경되면 연동 수정이 필요합니다.
- 제한 안내는 확인 후에만 표시합니다. 검사가 끝나기 전에는 경주에 참여할 수 없고, 입력을 수정하면 승인을 취소합니다. HTTP 확인 API와 WebSocket 방 생성·입장 모두 서버 검사를 거치므로 화면을 건너뛴 요청도 차단합니다.
- 준비·참가 대기실은 왼쪽을 바라보는 정적인 말 이미지로 표시하며 회전 기능은 없습니다. 밤색·황금빛·검정·흰색·얼룩·회색 반점·장밋빛·모래빛 8종을 서버가 정한 고유 레인에 연결합니다. 같은 방의 참가자는 모두 서로 다른 말을 받으며, 모든 브라우저에서 같은 참가자를 같은 이미지로 표시합니다. 각 말은 안장과 안장보를 착용하고 서버가 배정한 순서에 따라 1~8번을 표시합니다. 말 위에는 `내 이름은 ???` 형식의 말풍선을 띄우고 이름 확인 후 실제 이름으로 바꿉니다.
- 초대 링크를 열면 현재 서버의 방 정보를 조회해 참가 인원과 다음으로 배정될 말을 미리 표시합니다. 초대 화면에서는 이름 옆 **완료** 버튼이 이름 확인과 방 입장을 연속으로 처리하며, 성공하면 바로 갱신된 참가 대기실을 표시합니다. 같은 이름은 입력 화면에서 바로 경고하고 실제 WebSocket 입장 시에도 다시 검사합니다.
- 혼자 달리기: 플레이어 1명 + AI 7마리. AI는 약 18~28초에 완주합니다.
- 친구와 달리기: 초대 링크로 실제 플레이어 2~8명이 참여합니다. AI를 추가하지 않습니다. 방장은 자신의 마이크 준비만 마치면 언제든 시작할 수 있습니다 — 다른 참가자가 이름 짓기 오류 등으로 준비를 마치지 못해도 방장의 시작을 막지 않습니다. 마이크가 연결되지 않은 채 경주가 시작된 참가자는 자동으로 키보드 체험 모드로 전환됩니다. 이미 지은 이름이 있으면 그 이름을, 아직 이름을 짓지 못했으면 무작위로 고른 이름을 사용합니다.
- 친구 대기실은 Firebase Realtime Database의 `rooms/{방 ID}`에 실시간으로 반영됩니다. 초대 링크를 연 WebSocket 연결 순서대로 빈 말 번호를 즉시 예약하며, 이름 확인이 끝나면 예약된 말에 이름을 붙입니다. 앱 전환·새로고침 등으로 연결이 끊기면 이름이 붙은 참가자와 방장 권한은 5분 동안 유지합니다. 같은 탭의 sessionStorage에 저장한 복구 토큰으로 돌아온 참가자는 기존 자리로 복구되며, 서버에 이전 연결이 남아 있어도 인증 후 새 연결로 교체합니다. 마이크 준비는 다시 확인합니다. 아직 이름을 붙이지 않은 예약 자리("이름 짓는 중")는 다른 브라우저에서 같은 링크를 다시 열어도 복구되지 않고 새 자리를 예약하므로, 연결이 끊기면 2초 후 자동 정리해 방장의 시작을 막지 않고 목록에서도 곧바로 사라집니다. 명시적인 나가기는 즉시 처리합니다. 경주 시작, 마지막 참가자의 퇴장·복구 시간 만료 또는 방 생성 후 30분 만료 시 저장된 방을 삭제합니다.
- 200m 코스, 기본 5m/s(18km/h), 최고 20m/s(72km/h). 최근 2초의 이름 반복 4회부터 최고 속도입니다. 최고 속도 고정이면 10초, 무음이면 40초입니다. 실제 음성 경주는 초기 가속과 인식 지연으로 10초보다 더 걸릴 수 있습니다.
- 한국어 인식의 공백을 무시하고 정확히 일치한 전체 이름만 셉니다. 중간 결과에서 최종 결과로 변경되어도 중복 가속하지 않습니다. 음량은 마이크 시각화에만 사용합니다.
- 경주에서는 인식된 전체 문장을 출력하지 않고, 말 이름의 인식된 앞부분만 글자색으로 표시합니다. 중간에 처음부터 다시 부르거나 인식 결과가 수정되면 현재 일치하는 앞부분으로 되돌립니다. 완성된 이름은 잠깐 전체를 강조한 뒤 다음 호출을 기다립니다. 1.5초간 진전 없는 부분 인식은 초기화하며 가속하지 않습니다.
- 출발 시 마이크 스트림은 유지하면서 인식기를 새로 생성해 대기실·카운트다운의 기록과 지연 이벤트를 버립니다. 노래방 방식의 색 변화는 브라우저 중간 인식 결과가 도착할 때 갱신되므로, 실제 발음 음소와 완전히 실시간으로 일치하지 않을 수 있습니다.
- 마이크 없이 **솔로 키보드 체험**도 가능합니다. 스페이스를 반복하거나 화면 버튼을 누릅니다. 길게 눌러 자동 반복하는 입력은 가속하지 않습니다.
- 모두 완주하거나 연결을 끊으면 방장이 재경주를 준비할 수 있습니다. 대기실에서 방장이 나가면 방장 권한을 다음 사람에게 넘깁니다. 경주 중 연결 종료는 기권 처리합니다.

## 음성 인식과 공유

안드로이드는 발화 단위 인식(`continuous: false`)으로 중간 문장이 최종 결과처럼 누적되는 현상을 피하고, 인식 종료 후 자동으로 다시 연결합니다. 한 발화에서는 최신 문장만 표시·집계하며, 문장 안에서 실제로 반복한 이름과 다음 발화의 같은 이름은 각각 셉니다. 재연결 사이에는 짧은 인식 공백이 생길 수 있습니다. iOS와 데스크톱은 연속 인식을 유지합니다.

Chrome에서 한국어 음성 인식을 확인하도록 구성했습니다. 브라우저·운영체제·인식 서비스에 따라 지원과 정확도가 다릅니다. 마이크 권한과 인식 서비스 인터넷 연결이 필요합니다. 미지원·권한 거부·연결 실패 시 이유와 재시도를 표시합니다.

마이크는 사용자가 연결 버튼을 누를 때 음성 인식 서비스가 직접 요청하며, 나가기·완주 시 종료됩니다. 모바일(아이폰·아이패드·안드로이드)은 별도의 음량 측정용 마이크를 열지 않고 인식 서비스의 발화 이벤트와 실제 인식 문장 수신에 반응해 막대를 표시합니다. 이 막대는 음량 대신 음성 인식 활동을 나타내며, 반응 후 약 0.5초 동안 서서히 내려갑니다. 설정 화면에는 최근 들린 말과 이름 인식 횟수를 함께 표시합니다. 데스크톱의 음량 측정은 선택 기능으로, 권한이나 오디오 초기화가 실패해도 음성 인식을 막지 않습니다. 시작 오류는 권한·서비스 제한·입력 장치·네트워크 원인을 구분해 표시합니다. Safari에서 서비스가 허용되지 않으면 Siri 또는 받아쓰기 설정도 확인하세요. ([WebKit 안내](https://webkit.org/blog/11648/new-webkit-features-in-safari-14-1/)) 게임 서버는 오디오와 인식 문장을 저장하거나 받지 않고 반복 횟수만 받습니다. 브라우저의 음성 인식 서비스에는 음성이 전송될 수 있습니다. [SpeechRecognition 문서](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)

iPhone/iPad에서는 마이크 연결 버튼으로 별도의 무음 Web Audio 세션을 시작합니다. 사운드 OFF에서도 오디오 처리를 유지하고, 지원되는 환경에서는 `navigator.audioSession.type = 'play-and-record'`를 설정하며 종료 시 기존 값을 복구합니다. 배경음 OFF 전환은 음성 인식 중인 iOS에서 재생 중단 대신 음소거를 사용합니다. 이는 [WebKit 음성 입력 세션 유지 문제](https://bugs.webkit.org/show_bug.cgi?id=317741)와 사용자의 사운드 ON/OFF 재현 결과에 대한 호환성 조치입니다. iOS 버전과 출력 장치에 따른 실제 인식·음악 출력은 기기에서 확인해야 합니다.

모바일은 마이크 시작 이벤트만으로 준비 완료를 표시하지 않습니다. 연결 후 이름을 불러 실제 인식 문장이 도착해야 준비를 완료하며, 15초 동안 결과가 없으면 마이크를 정리하고 재연결을 안내합니다. iOS의 인식기 교체는 기존 인식기의 종료 이벤트를 기다립니다(종료 이벤트가 없으면 1초 후 재시도). 인스타그램 접속 시 Safari/Chrome 앱에서 열도록 주소 복사 안내를 표시하며, 인앱 브라우저의 서비스 거부를 Siri 설정 문제로 단정하지 않습니다. [WebKit 인앱 음성 인식 권한 설명](https://bugs.webkit.org/show_bug.cgi?id=239816)

외부 친구에게 보내려면 **HTTPS 공개 배포**가 필요합니다. localhost 링크는 현재 컴퓨터에서만 열립니다. 마이크는 보안 컨텍스트(HTTPS 또는 localhost)에서 동작합니다. WebSocket을 지원하는 Node/Docker 호스팅에 배포하세요. `Dockerfile`, `render.yaml`을 제공합니다. 배포된 주소에서 생성한 초대 링크는 자동으로 공개 주소를 사용합니다.

GitHub Pages를 화면 주소로 유지하면서 서버를 분리할 때는 현재 Docker 이미지를 Cloud Run에 배포합니다. Cloud Run 주소를 GitHub 저장소의 Actions 변수 `VITE_SERVER_ORIGIN`에 저장하면 Pages 빌드가 이름 확인 API와 WebSocket을 그 서버에 연결합니다. 서버의 `FRONTEND_ORIGINS`에는 `https://meoyaho.github.io`를 설정합니다. 현재 경주 상태가 단일 프로세스 메모리에 있으므로 Cloud Run 최대 인스턴스는 1개로 제한해야 합니다.

현재 GitHub Actions는 화면만 배포합니다. `server/` 또는 서버에서 사용하는 `shared/` 코드를 수정했다면 Cloud Run도 업데이트해야 공개 사이트에 적용됩니다. 로컬 서버 재시작은 공개 서버에 영향을 주지 않습니다.

```sh
gcloud run deploy horse-name-server --source . --project horse-name --region asia-northeast3 --max-instances 1
```

소스 업로드에서 `.env` 등 로컬 설정은 `.gcloudignore`로 제외합니다. 기존 Cloud Run 환경변수는 유지됩니다. 서버 교체 시 진행 중인 방은 종료될 수 있습니다.

## 운영 범위

친구 대기실은 Firebase Realtime Database에도 반영하고 경주와 연결 상태는 단일 Node 서버 메모리에서 관리합니다. 같은 서버 프로세스에 대한 재접속을 지원하지만, 서버 재시작 후 Firebase에서 방을 재구성하는 기능은 없어 서버가 재시작되면 기존 방도 종료됩니다. 여러 Node 서버에서 동시에 방을 처리하려면 별도의 서버 조정 계층이 필요합니다. 서버가 속도·거리·결과를 계산하고 입력 빈도를 제한하지만, 클라이언트가 보낸 반복 횟수의 실제 음성 여부까지 증명하는 경쟁용 부정행위 방지는 포함하지 않습니다.

3D 말은 `src/horse-model.js`에서 몸통·목·어깨를 부드럽게 연결한 표면, 굽은 뒷다리, 갈기·꼬리·가죽 안장으로 제작합니다. 이 모델은 경주에만 사용합니다. 준비·대기 화면의 PNG 이미지는 `public/horses/`에 보관합니다. 심즈의 캐릭터 제작 화면에서 영감을 받은 자체 모델이며 게임 원본 자산은 사용하지 않습니다. 베팅·결제 기능은 없습니다.
